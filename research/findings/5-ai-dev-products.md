# Alibaba AI, developer and productivity offerings for product-need questions (Qoder and others)

Researched 2026-10-31 by one agent, then fact-checked by an independent agent that tried to refute each load-bearing claim. 21 findings; fact-check verdicts: 8 confirmed, 9 partially-true. Findings without a verdict were high-confidence and not load-bearing, so they were not re-checked.

## Summary

Product-need answers are feasible, but only from a curated catalog with dates on every entry. In 2026 Alibaba renamed or merged at least 12 AI, developer and productivity offerings, and several answers that look obvious are wrong for international users. Two anchor answers are verified. For coding and engineering-team agents, the answer is Qoder (qoder.com, Singapore operating entity): Teams costs $40/seat/month with 3,000 credits per seat, and Enterprise costs $20/seat plus shared credits. Both bundle the new Qoder desktop agent, the IDE, the JetBrains plugin, the CLI, QoderWork, QoderWake, Cloud Agents and Mobile. For non-developer workplace agents, the answer is QwenWork: international beta since 2026-08-26, Enterprise Standard $30/seat/month. Tongyi Lingma is now Qoder CN, which is hosted in China and priced in CNY, so the model's uncatalogued answer is wrong for international users. Model Studio's no-code agent/workflow builder and knowledge base are restricted on the international site to users who created applications in Singapore before 2025-04-21 (docs updated 2026-10-11). Chatbot and custom-agent needs must therefore map to Model Studio APIs (Responses API with MCP and built-in tools) combined with AgentCore (Singapore), AgentRun, AgentBay or Agent Sandbox, AI Gateway, a vector store and guardrails, or to Dify on ACK. Coding Plan ($50/month) and Token Plan (team seats $20-$200) are interactive-only subscriptions. They are the right answer for 'use Qwen in Claude Code/Cursor', but never for app backends, including this app's own backend. Data-analyst, contractor-desktop and voice-agent needs map cleanly to Quick BI AIPro/Smart Q, DMS Data Agent, the DataWorks Agent, Elastic Desktop Service (EDS) Enterprise and IMS Real-time Conversational AI. Gaps remain: I found no self-serve international contact-center SaaS (Cloud Contact Center, AI Cloud Call Service (AICCS) and Cloud Application Platform (CAP)/Function AI are documented only on the China site), and pricing and regions for AgentCore and Agentic Computer are partly unpublished. There is no hard blocker. The build needs a catalog of about 35-40 entries with aliases, availability, purchase model and prices with as-of dates, plus the need-to-product intent table in artifacts.

## Recommended approach

1) Build an 'offerings' catalog (about 35-40 entries for this area) separate from the infrastructure catalog. Fields: id, display_name, aliases[], category (coding | workplace-agent | agent-platform | agent-runtime | model-api | data-ai | rag-store | desktop | voice | security | gateway), audience, kind (saas_seat | subscription_plan | cloud_payg | open_source | contact_sales), price_summary with as_of date, availability (intl | china_only | restricted | announced, plus regions[]), url, pairs_with[], not_for[] and status. The product cards and aliases in artifacts can seed it directly.

2) Add a need->product intent table (in artifacts) as retrieval context, plus disambiguation rules. For 'AI agent my team can use', default to Qoder (Teams) as primary. Show QwenWork for non-developers, QoderWake/Agentic Computer for always-on agents, and AgentCore for building your own. If the audience is unclear, the console asks one question ('developers or whole company?'). Assume an international customer unless mainland China is stated.

3) For product-need questions, render a 'solution map' instead of a VPC architecture. Lanes: People/Team -> SaaS products (seat badge, $/seat as-of) -> Model service (Model Studio/Qwen Cloud, PAYG) -> Cloud resources (PAYG). Group rule: SaaS and Model Studio nodes never sit inside a VPC group. Hover text comes from the catalog's 'why' plus availability and restriction notes. The product panel lists purchase path (qoder.com vs Alibaba Cloud Marketplace vs console) and price as-of date.

4) Prompting: send compact catalog rows (id | name | 1-line why | kind | availability) for this category only, to keep the prompt cache warm. Use qwen3.8-max with thinking off, as already measured. Validate ops against catalog IDs and drop unknown IDs. Never let the model state prices; the UI injects them from the catalog.

5) Run an eval set of the 20 needs in artifacts with expected primary IDs, including international vs China and 'restricted' traps (Lingma, Model Studio agent app, Cloud Contact Center). Rerun it on every catalog refresh.

6) Refresh the catalog monthly by hand plus a slow script, from these sources: docs.qoder.com/llms.txt and .md pages, the qoder.com pricing JSON, docs.qwencloud.com, the alibabacloud.com notices list, AgentCore/AgentBay/QwenWork product pages, and the Model Studio help pages (application-introduction restriction, coding-plan).
