# Architecture icons, reference architectures, overlapping Alibaba tools (CADT) and prior art

Researched 2026-10-31 by one agent, then fact-checked by an independent agent that tried to refute each load-bearing claim. 19 findings; fact-check verdicts: 5 partially-true, 9 confirmed. Findings without a verdict were high-confidence and not load-bearing, so they were not re-checked.

## Summary

Alibaba Cloud does not publish a current, licensed architecture icon kit that third parties may use. The old help page offering PPT and Visio icons (doc-detail/67830) was last archived in September 2024 and no longer exists. The de facto official set is the "阿里云设计中心" (Alibaba Cloud Design Center) account on iconfont.cn: 286 orange glyphs from 2022, collection last updated 2024-11-18, with an empty license field. draw.io's built-in Alibaba Cloud library has 273 entries. Neither set covers 2025-2026 products such as Model Studio, Qwen, PAI, Qoder, ESA or KMS. The Website Terms of Use (updated Sep 04, 2026) say ALIBABA, ALIYUN, QWEN and similar names "and related icons and logos" are protected marks and forbid unauthorized use. They also forbid copying, systematically compiling or scraping Platform content, and Alibaba publishes no brand guidelines for third parties. Two consequences follow: the app should use its own icon system and label products by name, and the knowledge-base pipeline carries contractual risk. Official grounding material exists but is uneven. The Architecture Center has 33 reference architectures and 12 quick starts from about 2019-2021, with nothing on AI, IoT or SaaS. The Well-Architected Framework (139 pages, fetchable through llms.txt) is current and includes an AI section updated Sep 23, 2026. Alibaba already ships part of this vision. The CADT AI Assistant turns natural language into deployable diagrams and accepts follow-up edits, but it is a public preview capped at 20 messages per day. Its supported-product list (in an older China-site English page) names about 15 infrastructure products, it takes 30 s to several minutes per generation, and it is documented only on the China site (the international page returns not-found). The aliyun.com AI Assistant gives text-only solution advice. Outside Alibaba, the open-source next-ai-draw-io (36.5k stars) and Visual Paradigm's AI Cloud Architecture Studio can already draw Alibaba Cloud diagrams from prompts. The opening is narrower than it looks: an international, explanation-first tool covering the full catalog (AI products and Qoder included) that draws live, with premium design. The build is feasible, provided it avoids Alibaba branding, ships its own icons, and hands off to CADT or draw.io rather than trying to deploy.

### F4 (high confidence)

draw.io has shipped an Alibaba Cloud shape library since its December 2024 release (blog post 2024-12-05). Shapes use style 'shape=mxgraph.alibaba_cloud.<name>' with fillColor=#FF6A00, and the sidebar file is copyright 2020-2025 JGraph. draw.io's code is Apache-2.0. Its README says the icon sets carry a separate restriction: no use in Atlassian products, while end-user diagram output is unrestricted. It also states 'Some icons are originally defined by third-party copyright holders; we have verified that all original licenses permit use in this project.' In issue #4086 the maintainers asked for 'the license that applies to the icons'. They then accepted the iconfont set on the strength of a contributor's report that customer service called it free to use, plus 'official posts' pointing to it. No license from Alibaba appears in the thread, which was last closed 2026-07-31.

**Implication:** draw.io's terms permit draw.io's own use; they do not sublicense Alibaba artwork to others. The app can export .drawio files that reference mxgraph.alibaba_cloud.* shape names. The user's draw.io then renders the icons, so the app gets an 'official-looking' export without redistributing the artwork.

## Blockers raised

- **major**: There is no licensed source of Alibaba Cloud product icons. ToU §7.1 claims 'related icons and logos' as marks and prohibits unauthorized use, and §2.3(a) prohibits copying images from the Platform. The iconfont and draw.io sets carry no license from Alibaba. **Mitigation:** Ship a custom, consistent icon system: about 30-40 category glyphs (compute, network, edge/security, database, storage, data, AI, devtools, SaaS) plus product-name labels or monogram tiles in the app's own palette. This also fixes the 2025-2026 coverage gaps and serves the 'impeccable design' requirement. For official-looking output, export .drawio files that reference mxgraph.alibaba_cloud.* shape names so the user's draw.io renders them. Use Alibaba glyphs in-app only after written permission, requested through an Alibaba Cloud BD or partner contact.
- **major**: Trademark and affiliation risk from heavy use of Alibaba, Alibaba Cloud and Qwen names in an AI tool. ToU §2.2 forbids misrepresenting affiliation, and only partners get badge rights. **Mitigation:** Keep Alibaba, Aliyun, Qwen and Qoder out of the product name, domain, logo and favicon, and do not use Alibaba orange #FF6A00 as the brand color. Use the names only to identify products, for example 'architecture advisor for Alibaba Cloud' in descriptive copy. Add a footer and About disclaimer: independent, not affiliated with, sponsored or endorsed by Alibaba Cloud, and the marks belong to their owners. Never call outputs 'official' or 'certified'. Link each product to its official page.
- **major**: Building the knowledge base by crawling Alibaba docs conflicts with ToU §2.3(b) (systematic retrieval to compile a database) and §2.4(e) (crawling, scraping or data-mining), even though llms.txt invites AI agents. The help center also triggers anti-bot challenges after a few dozen requests. A violation could affect the user's own Alibaba Cloud account. **Mitigation:** Ask Alibaba Cloud for written permission. Until then, ingest only through the official llms.txt and .md endpoints, slowly and with caching, and never bypass anti-bot challenges. Store paraphrased facts (name, one-line purpose, category, placement rules) with source URLs rather than copying doc text. Prefer structured metadata sources and hand-curated entries, and do not redistribute the docs.
- **minor**: Competitive overlap: CADT AI Assistant (Alibaba first-party, evolving), Visual Paradigm AI Cloud Architecture Studio (supports Alibaba Cloud) and the open-source next-ai-draw-io (draw.io Alibaba shapes plus Qwen) already cover 'prompt to Alibaba diagram'. **Mitigation:** Position the app as international and English-first, explanation-first (hover 'why', reasons panel, alternatives), drawing live in seconds, covering the full catalog including AI products, devtools and SaaS such as Qoder and Model Studio, and requiring no Alibaba login. Hand off to CADT, draw.io, ROS or Terraform instead of competing on deployment.
- **minor**: Icon coverage gaps: no official glyphs exist for Model Studio, Qwen, PAI, Qoder, ESA, KMS, AgentRun, AgentCore and other 2025-2026 products, which are central to this app. **Mitigation:** Use the category-glyph plus monogram fallback in every case, so the diagram looks uniform whether or not an official icon exists.

- Doc crawling (rated major): this is closer to moderate. The ToU text is confirmed and has no carve-out for llms.txt, and the anti-bot layer is real and dates back to at least 2024. But the knowledge base does not need large-scale doc crawling. Licensed structured sources exist for the product, code and endpoint backbone: aliyun/aliyun-openapi-meta (Apache-2.0, pushed 2026-10-30), aliyun/aliyun-cli (Apache-2.0) and aliyun/terraform-provider-alicloud (MPL-2.0). The few hundred curated 'purpose and placement' entries can be hand-written with source links, and Alibaba itself publishes llms.txt and .md files for LLMs and AI agents. The account-impact concern is real (ToU §2.8 and §3.7 allow suspension), so ingestion should run from an identity other than the user's main account and must never solve challenges. Note that www.alibabacloud.com robots.txt also disallows /*.json and /api/*.
- Competitive overlap (rated minor): fine for feasibility, but understated for product strategy, where I'd call it moderate. Missing from the list: (1) draw.io's own built-in AI Generate tool (Aug 4, 2026 update: chat refinement, attach a page or selection, bring-your-own keys including self-hosted compatible APIs) on top of its 273-shape Alibaba library; (2) aliyun.com's AI assistant (阿里云 AI 助理), which offers solution recommendations and product consulting; (3) CADT AI, already packaged as an agent skill and advertised on the international CADT stub page. Live progressive drawing alone is not unique, since CADT also creates resources one by one while streaming. The defensible edges are speed (seconds versus minutes), explanations, breadth beyond infrastructure, and an international, English-first product.
- Icon coverage gaps (rated minor): agree. Note also that a .drawio export would fall back to generic shapes for exactly the AI and devtools products the app emphasizes (Model Studio, Qwen, Qoder, AgentRun, AgentCore, ESA), so the in-app fallback design must carry over to the export.

## Fact-checker: missed risks

- The official China-site icon page https://cn.aliyun.com/icon/download.html (no equivalent on alibabacloud.com) states explicit icon IP terms: prior permission required, no modification, non-transferable. Its ZIP and PNG files return 403 AccessDenied to direct requests. So there is no usable official download path, and asking permission is the only legitimate one.
- help.aliyun.com/document_detail/67830.html now 301-redirects to the Alibaba Cloud Design Center iconfont page (uid 6856114). This is a maintained official pointer, not a license. It identifies the owner to contact for permission (Alibaba Cloud Design Center).
- draw.io itself is a free, mainstream substitute. Its Generate tool, updated 2026-08-04 (https://www.drawio.com/blog/updated-generate/), supports follow-up refinement, attaching the current page or selection, bring-your-own keys, and self-hosted compatible models. Its built-in Alibaba Cloud library has 273 shapes.
- First-party overlap with the 'I need X' mode: aliyun.com's AI assistant (阿里云 AI 助理, https://cn.aliyun.com/ai-assistant/product, checked 2026-10-31) offers solution recommendation and product consulting. alibabacloud.com has an 'AI Assistant' page and chat widget whose capabilities I could not read.
- Official sources lag renames. The international llms.txt still listed 'Cloud Skills Portal' on 2026-10-31, although it was renamed Cloud Agent Catalog on 2026-08-26. The knowledge base needs an alias table and a periodic scan of alibabacloud.com/en/notice product_change_* notices.
- Pattern sources the researcher omitted: CADT 'Official Solutions' (pre-built scenario templates in the console) and the bpstudio Template/Application APIs are a current, first-party source of reference topologies, though they need a login or AccessKey.
- Agent-skill channel: AWS replaced its diagram MCP server with a skill that emits draw.io XML with official AWS4 icons plus a validation hook. Azure exposes its Deployment Agent via microsoft/azure-skills, and Alibaba ships CADT drawing as a skill. Coding agents such as Claude Code and Qoder may become the main competing channel.
- aliyun/alibabacloud-aiops-skills has no repository license, while ClawHub lists the skill as MIT-0. Copying its SKILL.md prompts or workflows is therefore not clearly licensed.
- The international ToU covers only alibabacloud.com and its marketplace. Content on help.aliyun.com and aliyun.com (the CADT AI docs, the tech-solution catalog) is governed by China-site legal terms, which neither the researcher nor I reviewed.
- CADT's international 'Generate cloud architectures' stub (Jun 02, 2026) already advertises natural-language generation. If CADT AI launches internationally, the first-party competitor gains the free, console-integrated, deployable path the app plans to hand off to.

## Recommended approach

Build the app as an independent advisor that explains and visualizes Alibaba Cloud architectures. It should not deploy and should not look official.

1. Icons and visual identity. Design an in-house icon system: category glyphs on tinted tiles with the product name as the primary label, and a monogram for products without a glyph. It must cover 100% of the catalog and follow the app's own design tokens, not Alibaba orange. Keep a mapping table from catalogId to draw.io shape name (273 names in the artifacts) so the app can export .drawio files that reference mxgraph.alibaba_cloud.* shapes. Add PNG/SVG export and a Markdown bill of materials with official doc links. Put an 'Alibaba icon style' toggle behind written permission.

2. Grounding. Build a curated pattern library in the system prompt and validators, drawn from the AI Well-Architected Framework (updated Sep 2026), the classic Well-Architected pillars and the Cloud Network WA guidelines. Use the 33 legacy reference architectures only for topology idioms, mapping old names to current ones (SLB to CLB/ALB/NLB, Apsara PolarDB to PolarDB). Encode placement rules as checks after each op, covering the errors already observed: request chain DNS, then ESA/CDN, then WAF, then ALB; managed and regional services such as Model Studio, SLS, ARMS, CloudMonitor, Security Center and Quick BI outside the VPC; zone and vSwitch nesting inside VPCs. Optionally borrow Intelligent Advisor rule names as review checks.

3. UX lessons from the prior art. Apply streamed ID-based ops in place, with stable layout and pulse highlights for added or changed nodes and fades for removed ones. Show a per-turn 'what changed' chip with undo and a version timeline. Send the current graph, including manual moves and deletes, on every turn, and let users @-mention a node to scope an edit. Ask at most one or two clarifying questions, with suggested-default chips and optimization presets (cost, HA, global, compliance). Make 'why', alternatives and a doc link first-class fields on every node: the hover cards and the collapsible product panel both read from them. Send SSE heartbeats during silent stretches.

4. Positioning. Call the app international, English-first, instant and full-catalog (AI, devtools and SaaS included, so 'I need an AI agent for my team' returns Qoder). Offer an 'Open in CADT'-style hand-off later, if CADT's template or import API turns out to work. Do not try to use CADT AI as the engine: it runs in cn-hangzhou, polls, takes 30-120 s and allows 20 messages a day.

5. Legal hygiene. Use a non-Alibaba product name and domain, a non-affiliation disclaimer, nominative mentions only, and no logos. Ingest the knowledge base slowly through llms.txt and store paraphrased facts with citations. Ask Alibaba Cloud for permission covering icons and doc ingestion before any commercial launch.
