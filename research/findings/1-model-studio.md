# Model Studio platform and qwen3.8-max capabilities, pricing and limits

Researched 2026-10-31 by one agent, then fact-checked by an independent agent that tried to refute each load-bearing claim. 21 findings; fact-check verdicts: 9 confirmed. Findings without a verdict were high-confidence and not load-bearing, so they were not re-checked.

## Summary

I checked the official International docs live on 2026-10-31. Twenty-two of the earlier run's downloaded pages were re-fetched and match today's versions byte-for-byte apart from tracking IDs. The one exception is the structured-output page, which changed on Oct 30. The docs are detailed: qwen3.8-max has its own model page, so nothing had to be inferred from qwen3.7-max. The model has a 1M-token context and 131,072 max output, and supports streaming with include_usage, function calling, json_object, web search and both implicit and explicit context caching on Singapore. It is a hybrid thinking model with thinking ON by default, and the default reasoning budget is 131k-262k tokens. That explains the multi-minute silent reasoning the main session measured, so every request must send enable_thinking:false (or reasoning_effort "none"), or at most reasoning_effort "low" (4,096 tokens). Singapore prices per 1M tokens are $2 in / $6 out for qwen3.8-max, the same in both modes and with no input-length tiers. Cache hits cost $0.25 (implicit) or $0.17 (explicit), and creating an explicit cache costs $2.50. qwen3.8-flash costs $0.15/$0.47 and qwen3.7-plus $0.40/$1.60 up to 256K input. Each model comes with 1M free tokens for 90 days. Rate limits are dynamic, per account and per model: qwen3.8-max gets 2M TPM below $8k monthly spend, about 75 fresh diagram requests per minute at roughly 26k tokens each, and the limit is also enforced per second. Limits can only be raised through a business manager. Three documented constraints favour the NDJSON-in-content protocol the main session already validated: tool_choice cannot be "required", and in thinking mode cannot force a specific function; tool_stream is off by default; and a note in the docs says json_schema is "not supported yet" for Singapore models. CORS is not documented anywhere. The official browser pattern is a temporary key minted by a backend (st-, valid 1-1800 s, inherits every permission of the parent key, cannot be revoked), so the app should run behind a backend proxy using a scoped key in a dedicated sub-workspace. Model Studio's knowledge bases, agent/workflow apps and prompt APIs are preview features that, in Singapore, only accounts which created apps there before 2025-04-21 can use, so the product catalog must be hosted by the app itself. The dashscope-intl domain that works with the user's key is the legacy shared domain: 600 s timeout, and the regions page says the DashScope domain gets no new features after 2026-09-30. The workspace-dedicated domain is the recommended one and should be tested. Verdict for this area: feasible, with no hard blockers.

## Findings

### F1 (high confidence)

qwen3.8-max is the 2.4T-parameter MoE flagship (~95B active), with image, text and video input and text output. The models page lists it as 'Complex reasoning and coding'. The Singapore/International release log dates it 2026-08-02, and the press release is datelined Hangzhou, August 3, 2026. The snapshot qwen3.8-max-0902 (alias qwen3.8-max-2026-09-02, released 2026-09-02) is described as an 'upgraded snapshot' with better coding, multi-tool orchestration and vision. qwen3.8-flash was released 2026-08-26. The pricing page gives no 'currently equivalent to' note for the qwen3.8-max alias, so it appears to point at the August release.

**Implication:** Use the qwen3.8-max alias as the user asked. qwen3.8-max-0902 is the same price and possibly better at multi-tool work, but has lower throughput limits (F12). Worth an A/B test; keep the model ID configurable.

### F2 (high confidence)

Limits for qwen3.8-max, qwen3.8-max-0902 and qwen3.8-flash (qwen3.7-plus has the same numbers): context window 1,000,000; max input 991,808 (983,616 in thinking mode); max output 131,072 in both modes; max chain-of-thought 262,144. **Implication:** A 24k-token catalog prompt plus the graph JSON is far below the limits; context size is not a constraint. Cap output with max_completion_tokens (F5).

### F3 (high confidence, load-bearing)

Thinking: qwen3.8-max and qwen3.8-flash are hybrid models with thinking ON by default. enable_thinking is not a standard OpenAI parameter: put it at the top level of the raw HTTP body, or in extra_body with the Python SDK. thinking_budget defaults to the model's max chain-of-thought (262,144); the same page also says the default is 131,072 when neither knob is set. reasoning_effort for qwen3.8 accepts xhigh (default), medium and low, which map to thinking_budget 262,144, 16,384 and 4,096. 'none' maps to enable_thinking=false, max/high map to xhigh, and minimal maps to low. Setting both reasoning_effort and thinking_budget returns an error. Thinking tokens are billed as output, at the same price as non-thinking output for qwen3.8-max.

**Implication:** The documented defaults explain the >300 s silent reasoning the main session measured. The backend must force enable_thinking:false (or reasoning_effort:'none') on every live-drawing request. If more quality is wanted, use reasoning_effort:'low' (4,096 budget) or thinking_budget of about 1,024 (measured first op at 7.5 s). Never ship the default.

### F4 (high confidence)

preserve_thinking defaults to true for qwen3.8-max and qwen3.8-flash (false for other models). The docs say: 'You must send back all historical reasoning_content in the reasoning_content field. Do NOT concatenate reasoning_content into the content field.' Historical reasoning that is sent back is billed as input tokens. If history lacks reasoning_content, no error is raised.

**Implication:** With thinking off nothing changes. If any turn uses thinking, the conversation store must keep each assistant message's reasoning_content and send it back in that field, or the request must set preserve_thinking:false explicitly to save input tokens.

Sources: https://www.alibabacloud.com/help/en/model-studio/qwen-api-via-openai-chat-completions (opened 2026-10-31); https://docs.modelstudio.console.alibabacloud.com/en/model-studio/qwen-api-via-openai-chat-completions (WebFetch 2026-10-31); https://www.alibabacloud.com/help/en/model-studio/deep-thinking (opened 2026-10-31)

### F5 (high confidence)

Streaming: stream:true returns SSE chunks. stream_options.include_usage (default false) puts usage only in the last chunk. Non-streaming calls time out after at least 300 s (500 RequestTimeOut: 'timeout error occurs after 300 seconds'). The request timeout is 600 s on the DashScope and trial domains and 3600 s on the workspace-dedicated domain. max_completion_tokens caps chain-of-thought plus answer (supported on Qwen3.7-Max and later) with up to 10 tokens of slack. max_tokens caps only the answer for Qwen and is marked to-be-deprecated.

**Implication:** Always stream with include_usage:true to log cached_tokens and reasoning_tokens. Set max_completion_tokens (for example 8192) as a runaway guard. Add our own watchdogs, because none of the documented timeouts would catch a 125 s stall.

Sources: https://www.alibabacloud.com/help/en/model-studio/qwen-api-via-openai-chat-completions (opened 2026-10-31); https://docs.modelstudio.console.alibabacloud.com/en/model-studio/regions (WebFetch 2026-10-31); https://docs.modelstudio.console.alibabacloud.com/en/model-studio/error-code (WebFetch 2026-10-31)

### F6 (high confidence, load-bearing)

Function calling is supported and parallel_tool_calls defaults to true, including in thinking mode. Qwen does not support tool_choice:'required'. In thinking mode, tool_choice 'required' or a forced {function} object makes the request fail. When streaming, the function name arrives in the first delta and the arguments arrive in chunks. However, tool_stream (default false; supported for qwen3.8-max text) means that tools with array or object parameters emit their arguments all at once unless tool_stream:true. Tool definitions are billed as input, and the docs recommend at most 20 tools.

**Implication:** This confirms the measured result that one tool call per diagram op is a poor fit: tool calls cannot be forced, and object-typed arguments are not streamed by default. Stream diagram ops as NDJSON in content and validate them server-side. Tools are only worth using for occasional actions such as a catalog lookup.

### F9 (high confidence, load-bearing)

Context cache comes in two mutually exclusive modes. Implicit cache is automatic, cannot be disabled, needs a prefix of at least 1,024 tokens, has no fixed TTL and does not guarantee a hit. Explicit cache uses cache_control {type:'ephemeral'} on system, user, assistant or tool message content: at least 1,024 tokens, 5-minute TTL that resets on each hit, up to 4 markers, and a 20-content-block lookback. Tool definitions are serialized into the system message, so tool order, field order and structure must stay identical. Caches are isolated per account and per model. Singapore prices for qwen3.8-max: implicit hit $0.25/M (12.5% of input), explicit creation $2.50/M (125%), explicit hit $0.17/M (8.5%). qwen3.8 models are listed as exceptions to the generic 20%/10% ratios.

**Implication:** Put the catalog and rules first, in one byte-stable system message, and put the graph JSON and user turn last. An explicit marker on the catalog block gives deterministic warm hits within 5 minutes (measured warm TTFT 1.0-2.8 s vs 13.9 s cold) and is the cheapest input path at $0.17/M. Implicit caching alone, as measured (2176/2339 cached tokens on follow-ups), is the fallback.

### F12 (high confidence, load-bearing)

Rate limits apply per Alibaba Cloud account and per model, summed across all workspaces and API keys. In Singapore, qwen3.8-max uses dynamic limits: TPM is tiered by monthly Model Studio spend at 2,000,000 (up to $8,000), 5,000,000 ($8,000-$140,000) and 10,000,000 (over $140,000). These are soft limits, so the real ceiling may be higher. RPM is described as 'relatively large' but no number is published. qwen3.8-max-0902 is fixed at 1,500,000 TPM. qwen3.8-flash gets 2.5M/5M/10M TPM. qwen3.7-plus has static limits of 15,000 RPM and 5,000,000 TPM, while its snapshot qwen3.7-plus-2026-05-26 gets only 60 RPM and 1M TPM. Limits may also be enforced per second (RPS = RPM/60, TPS = TPM/60), and sudden spikes trigger 429 Throttling.BurstRate. To raise limits, contact the business or account manager; topping up the balance does not raise them.

**Implication:** At Tier 1, 2M TPM allows about 75 new 26k-token diagram requests per minute, and the per-second limit (about 33k tokens/s) allows about 1.3 per second. A public launch needs a server-side queue, exponential backoff on 429, a qwen3.8-flash fallback, a smaller retrieved catalog subset where possible, and a quota request if traffic grows. Use the aliases, not dated snapshots.

## Recommended approach

Call OpenAI-compatible Chat Completions on Singapore from a backend proxy, never from the browser.
