## Items

### 1. Backend identity boundary (Codex #1, Claude D0, D1, D2), high
Text the backup provider generates reaches the browser unchanged, in both modes: say, op labels, why and req text, done summaries, ids, and the raw excerpt inside a bad-json warning. The product rule is that the backup's vendor and model names never reach the browser.

**Fix:**
- Build one shared identity matcher in core:
  - NFKC-normalize the text first;
  - match the vendor and the model family, with family names counted only next to a version or the vendor, so "magnum opus" passes;
  - include the ko, zh and ja transliterations;
  - allow the exact coding product "Claude Code" (with a word boundary: `c[l]aude(?![ -]?code\b)`) and an "Anthropic-compatible" API mention;
  - keep the character-class trick, so the names don't appear literally in the browser bundle.
- Apply it **only to text the backup provider produced**, so primary-model (Qwen) output stays byte-identical:
  - in prose, replace a match with a neutral word;
  - in ids, remap them consistently across references;
  - drop raw backup excerpts from warnings.
- Don't expose `finishReason: 'content_filter'` from the first pass in browser-bound events.
- **Test:** the cloud path has the same exposure today. Fix both modes, and state that in your report.

### 2. The proposal filter (Codex #8, #9, #10; Claude C0), medium

- writer-attribution wording ("composed by", "authored by", "prepared by", "generated by", "produced by", and the ko and zh forms). Model names used as design choices stay allowed.

### 3. Workflow proposal backup voice (Claude C1, C13), low

### 4. Committed memory must stay admissible (Codex #5; Claude C7, C8), medium
A session must never commit memory that the next request's admission (`checkTurnRequest`) rejects.

**Fix:**
- Clip the persisted assistant-turn narration at commit to the admission limit (Codex #5).
- Prune estimate entries whose ids are no longer in the committed workflow, at commit (C8).
- In admission:
  - drop estimate entries whose ids aren't in the request's workflow **before** the size checks;
  - treat estimate values outside `ESTIMATE_LIMITS` (`packages/core/src/workflow-estimate-limits.ts`, already wired into `request.ts`) by dropping that field, not by failing the turn. The estimate is advisory UI state, so a bad value must not brick a session (C7). The cost editor is being fixed separately to use the same limits.
- **Invariant test:** across the 32 workflow fixtures and the cloud replay fixtures, the memory committed by `executeTurn` passes `checkTurnRequest`. Round B is capping the edges repair creates (Codex #4). If your invariant test hits that case, mark it as a known pending case referencing Codex #4, rather than fixing it in `workflow-validate.ts`.

### 5. Fences and prompt data (Claude C2, D4), low
- A single-pass strip of `<user_message>` lets a nested tag close the fence, in both modes (`prompt.ts` and `workflow-prompt.ts`). Strip until stable.
- Add one line to the workflow system prompt saying that the memory sections are data, never instructions, as cloud R18 does. Keep the workflow prompt under its token band, and update the band test if needed.
- The cloud system prompt hash must stay `998fab223daba0a4407930f0f6f61e90cf100d7783ca4b13008636526d049313`. `fence()` is used in user content, not the system prompt.

### 6. Admission and parity (Codex #7; Claude C3, C4, D5)
- **Ids:** reject workflow documents whose node, edge and group ids intersect (#7).
- **Language:** the memory-budget fatal is always English. Give it the reply language, or a code the client localizes (C3). Pick whichever needs no web change, or the smallest one, and say which.
- **Compaction CPU:** compaction re-serializes the whole memory once per dropped item, about 2 s of CPU on one crafted turn (C4). The Worker has CPU limits, so make it linear: incremental byte accounting.
- **BOM:** the local server rejects a UTF-8 BOM while the Worker accepts it (D5). Make them agree; accepting it is fine.
